# 数值卡字符替换（replace）— 设计与验证说明

> 引入版本：2026-11-15
> 作用：给数值卡（`value`）和拆分块（`split`）配置「把某些字符换成别的」，配置写入设备 JSON，供设备端 LVGL 重绘时执行同一套规则。

---

## 1. 为什么需要这个功能

接口返回的字段里常有需要清洗的字符，例如：

- `DRUG_FEEDBACK: "花粉类过敏,青霉素过敏"` —— 逗号在窄卡片里显得拥挤
- `SAFETAKECARE: "防窒息,防坠床,防跌倒"` —— 想看成分隔更松的排版

以前只能在设备端硬编码，改一处要重新烧固件。现在把规则放进 Schema，编辑一次、设备端照做。

---

## 2. 数据结构

### 2.1 字段位置

`HmiItem`（卡片内的一个格子）上新增可选字段 `replace`：

```ts
export interface HmiItem {
  type: 'label' | 'value' | 'qrcode' | 'split'
  // ... 其他字段
  /** 字符替换表，按数组顺序逐条执行 */
  replace?: HmiReplaceRule[]
}

export interface HmiReplaceRule {
  from: string   // 待替换的字面文本
  to: string     // 替换结果；留空表示删除
}
```

### 2.2 为什么用数组而不是对象

对象（`{ ",": " " }`）的键在 JS 里是有序的，但序列化、跨语言解析、设备端 C 实现都容易丢顺序。
而替换**有先后依赖**（例如先把 `,` 换成 `X`，再把 `X` 换成 `Y`），所以必须用数组保证顺序。

### 2.3 转义约定

`to` 字段支持四种转义，在渲染时还原成真实字符：

| 写法 | 实际字符 | 说明 |
|---|---|---|
| `\s` | 一个空格 | 最常用，规避「看不出几个空格」的问题 |
| `\t` | 制表符 | |
| `\n` | 换行 | LVGL 里通常需要多行文本支持 |
| `\\` | 反斜杠本身 | |
| 其他 `\x` | 原样保留 `\x` | 不吞掉路径类文本里的反斜杠 |

**为什么推荐 `\s` 而不是直接敲空格**：

1. 输入框里两个空格和零个空格肉眼分不出，改错了也不知道
2. 首尾空格容易被表单、剪贴板、某些编辑器保存时 trim 掉
3. JSON 里 `"to": "  "` 看不出是几个空格，`"to": "\\s\\s"` 一眼就是两个

直接敲真实空格也仍然可用，两种都能跑。

## 3. 执行顺序（重点）

### 3.1 数值卡（`value`）

**字符替换 → 遮罩**

```ts
applyMask(applyReplace(raw, item.replace), item.mask, item.mask_at, item.mask_n)
```

先替换再遮罩，意味着遮罩作用于替换后的文本。例如：

- 原值 `"张三,李四"`，规则 `,` → `\s`
- 替换后 `"张三 李四"`
- 遮罩（第 2 字起 1 个，符号 `*`）→ `"张* 李四"`

### 3.2 拆分块（`split`）

**先按分隔符切分 → 再对每一块替换**

```ts
valueText(item.prop)
  .split(sep)
  .map((part) => applyReplace(part.trim(), item.replace))
  .filter(Boolean)
```

这个顺序很重要。如果反过来（先替换再切分），当你把分隔符本身替换掉时就会切不开：

- 原值 `"防窒息,防坠床"`，分隔符 `,`
- 若先替换 `,` → `\s`，变成 `"防窒息 防坠床"`，再按 `,` 切 → 只有一块 ✗
- 正确做法：先切成 `["防窒息", "防坠床"]`，再逐块替换 ✓

### 3.3 拆分块与颜色字典的交互

拆分块每块的颜色是按文字查 `doc.colors` 的。替换后文字变了，可能查不到字典：

```ts
background: lookupColor(doc.colors, part, paintColor(item.default_color, doc, '#7C7C7C'))
```

**行为**：替换后的文字若不在颜色字典里，回落到 `default_color`（缺省 `#7C7C7C`）。
如果希望替换后仍能匹配颜色，要么不要替换用于查色的关键字，要么把替换后的文字也加进字典。

## 4. 界面操作

### 4.1 入口

| 卡片类型 | 位置 |
|---|---|
| 数值卡（`value`） | 右侧属性面板「遮罩」区域下方 |
| 拆分块（`split`） | 右侧属性面板「默认底色」下方 |

`label` / `qrcode` 不显示此区块（没有可替换的文本来源）。

### 4.2 操作步骤

1. 点「+ 添加」新增一条规则，出现两个输入框：`原文` → `替换为`
2. 左边填待替换的字面文本（如 `,`）
3. 右边填替换结果（如 `\s\s` 表示两个空格）
4. 改完立即在画布上生效，无需保存
5. 点每行右侧的 `×` 删除该条规则

### 4.3 边界行为

| 情况 | 行为 |
|---|---|
| `原文` 为空 | 该条忽略，不影响结果 |
| `替换为` 为空 | 删除该字符（例如 `,` → 空 = 移除所有逗号） |
| 没有规则 | 不写 `replace` 字段，设备 JSON 保持干净 |
| 多条规则 | 按列表顺序执行，前一条结果进入后一条 |

## 5. 设备 JSON 形式

导出（「设备 JSON」按钮 / 发布）时，`replace` 原样写进 item：

```json
{
  "type": "value",
  "prop": "DRUG_FEEDBACK",
  "title": "敏",
  "replace": [
    { "from": ",", "to": "\\s\\s" }
  ]
}
```

规则清理逻辑：

- `from` 为空的条目会被丢弃
- 所有条目都被丢弃时，整个 `replace` 字段不写（等价于未配置）

## 6. 设备端（LVGL）实现要点

### 6.1 需要做的事

解析 item 的 `replace` 数组，对字段取到的文本按顺序执行：

```c
// 伪代码
char *text = get_field_value(obj, item->prop);
for (int i = 0; i < item->replace_count; i++) {
    char *to = unescape_replace_value(item->replace[i].to);  // \s -> ' ', \t -> '\t', ...
    text = replace_all(text, item->replace[i].from, to);     // 全部替换，不是只替换第一个
}
lv_label_set_text(label, text);
```

三个必须对齐的点：

1. **全部替换**，不是只替换第一处（等价 `split/join`，不是 `str.replace`）
2. **按数组顺序**执行，前一条结果进入后一条
3. **先替换再遮罩**（数值卡）；**先切分再逐块替换**（拆分块）
4. `to` 里的转义要先还原再替换

### 6.2 字面匹配，不支持正则

`from` 是**纯字面**匹配，不是正则。这样 C 端实现最简单（`strstr` 或逐字符扫描即可）。

当前做不到的需求（如果以后需要再加）：

- 「连续多个逗号换成一个」—— 字面匹配无法表达
- 「忽略大小写」

如后续要支持，建议加可选字段 `mode: "literal" | "regex"`，默认为 `literal`，保持向后兼容。

## 9. 已知限制

1. **不支持正则** —— 见 6.2。
2. **不支持多字符匹配的转义** —— `from` 也是字面文本，不能写 `\s` 去匹配空格。如需匹配空格，直接填一个真实空格。
3. **拆分块颜色可能失配** —— 见 3.3。
4. **`label` / `qrcode` 无此功能** —— 只有 `value` 和 `split` 会在属性面板显示「字符替换」区块。
